# 后端 API 错误处理规范

## 目标

统一错误处理可以让前端、日志和调用方都能稳定理解接口失败原因。后端不应该直接返回堆栈信息，也不应该让不同接口使用完全不同的错误格式。

## 错误结构

推荐返回统一 JSON：

```json
{
  "message": "用户可读错误",
  "code": "ERROR_CODE",
  "details": {}
}
```

## 常见错误类型

- 参数错误：请求字段缺失、类型不正确或路径非法。
- 权限错误：用户未登录或缺少操作权限。
- 资源错误：文章、用户或配置不存在。
- 外部依赖错误：AI 服务、检索服务、数据库暂时不可用。
- 系统错误：未预期异常，需要记录日志并返回通用提示。

## 实践建议

业务代码可以抛出带 `status` 的错误，由统一入口转换为响应。日志中保留详细错误，响应中只返回对用户有帮助的简短说明。
