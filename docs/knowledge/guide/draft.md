# 什么是 MCP、Agent、Skills？

在 AI 应用开发中，**MCP、Agent、Skills** 是三个经常一起出现的概念。它们分别解决不同的问题：

- **MCP**：负责“怎么连接外部工具和数据”
- **Agent**：负责“怎么理解任务、规划步骤并执行”
- **Skills**：负责“具体能做什么”

如果把 AI 系统类比成一个人：

- **Agent** 是这个人本身，能够思考和行动
- **Skills** 是这个人掌握的各种技能
- **MCP** 是这个人和外界工具、资源沟通的标准接口

---

## 1. MCP 是什么？

**MCP（Model Context Protocol）**，中文一般叫“模型上下文协议”，是一种用于连接 AI 模型与外部系统的**标准协议**。

它的作用类似于一个“通用插口”，让 AI 应用可以用统一方式访问：

- 文件系统
- 数据库
- 搜索引擎
- GitHub
- 日历、邮件
- 企业内部系统
- 各类自定义工具

### MCP 解决什么问题？

在没有统一协议之前，每接入一个工具都要单独开发一套对接逻辑。  
而 MCP 提供了标准化方式，让模型和工具之间的集成更一致、更容易维护。

### 简单理解

MCP 解决的是：

> AI 要怎么“安全、规范、统一”地接入外部能力？

---

## 2. Agent 是什么？

**Agent（智能体）** 指的是能够**自主理解任务、规划步骤并执行动作**的 AI 程序。

它不只是回答问题，还会根据目标主动完成任务，通常会包含以下能力：

- 任务理解
- 目标拆解
- 步骤规划
- 工具调用
- 结果观察
- 迭代执行
- 任务收尾

### 举个例子

你对 Agent 说：

> 帮我整理这周会议纪要，并发给相关同事。

Agent 可能会自动完成这些步骤：

1. 读取会议记录
2. 提炼重点
3. 找到相关联系人
4. 生成邮件内容
5. 发送给对应人员

### 简单理解

Agent 解决的是：

> AI 要怎么“像人一样完成任务”？

---

## 3. Skills 是什么？

**Skills（技能）** 通常指 AI 系统中可复用的具体能力模块，或者面向某类任务的专业工作流能力。

它可以理解为：

- 一组预定义能力
- 一个具体任务处理模块
- Agent 可调用的“技能包”

### 常见的 Skills 例子

- 写邮件
- 总结文档
- 翻译
- 生成代码
- 提取表格信息
- 生成报告
- 查询知识库
- 整理会议纪要

### 在不同平台里的含义

不同产品里，Skills 的实现方式可能不同，例如：

- 固定功能模块
- 工作流模板
- 专门的任务能力
- 可以被 Agent 调用的工具能力

### 简单理解

Skills 解决的是：

> AI “具体能做什么”？

---

## 4. MCP、Agent、Skills 的关系

三者可以这样理解：

- **MCP** 是连接外部世界的标准接口
- **Agent** 是负责思考和执行的智能体
- **Skills** 是 Agent 可以使用的具体能力

### 用一个类比说明

把 AI 系统想成一个人：

- **Agent** = 这个人，会思考、会行动
- **Skills** = 这个人掌握的本领，比如写作、翻译、分析
- **MCP** = 这个人和外部工具、资源连接的方式

### 关系图

```text
用户任务
   ↓
Agent（理解任务、规划步骤）
   ↓
Skills（完成具体能力）
   ↓
MCP（连接外部工具/系统）
   ↓
数据库、文件、邮件、搜索等外部资源
```

---

## 5. 一个实际案例

假设你要做一个“自动报表助手”。

### Agent 的职责
Agent 负责整体任务推进，例如：

- 判断要先查数据还是先画图
- 决定报表结构
- 控制执行顺序
- 在结果不理想时继续调整

### Skills 的职责
Skills 负责具体动作，例如：

- 查询数据库
- 生成图表
- 写总结
- 导出 PDF
- 发送邮件

### MCP 的职责
MCP 负责让这个助手通过统一方式访问外部系统，例如：

- 通过标准协议访问数据库
- 读取文件
- 调用邮件服务
- 获取内部文档

---

## 6. 三者的区别

| 概念 | 核心作用 | 关注点 | 类比 |
|------|----------|--------|------|
| MCP | 连接外部工具和数据 | 怎么接入 | 插口 / 协议 |
| Agent | 规划和执行任务 | 怎么做事 | 行动者 |
| Skills | 完成具体能力 | 能做什么 | 技能 / 工具箱 |

---

## 7. 什么时候需要关注它们？

### 关注 MCP
如果你在做：

- 工具集成
- 多系统对接
- 标准化访问外部数据
- AI 与企业内部系统联动

你就需要关注 MCP。

### 关注 Agent
如果你在做：

- 自动化任务执行
- 多步骤推理
- 复杂工作流
- 自主规划和决策系统

你就需要关注 Agent。

### 关注 Skills
如果你在做：

- 给 Agent 添加能力
- 复用已有任务模板
- 构建标准任务模块
- 扩展 AI 的业务处理能力

你就需要关注 Skills。

---

## 8. 一句话总结

- **MCP**：标准协议，负责“怎么接工具”
- **Agent**：智能执行体，负责“怎么做任务”
- **Skills**：具体能力模块，负责“能做什么”

---

## 9. 常见误区

### 误区 1：MCP 就是 Agent
不是。  
MCP 只是连接协议，不负责主动思考和执行任务。

### 误区 2：Skills 就是工具
不完全是。  
Skills 更像是“能力单元”，有时会调用工具，但它本身更强调任务能力而不是单纯接口。

### 误区 3：Agent 不需要 MCP
在需要连接外部系统的场景下，Agent 往往需要 MCP 或类似机制来访问工具和数据。

---

## 10. 快速记忆法

可以用一句话记住：

> Agent 负责做事，Skills 负责本事，MCP 负责连接外部世界。

---

## 11. 小结

MCP、Agent、Skills 是 AI 应用设计中三个层次不同、但经常协同工作的概念：

- **MCP** 让模型更容易接入外部资源
- **Agent** 让 AI 能自主完成复杂任务
- **Skills** 让 Agent 拥有可复用、可扩展的具体能力

理解它们之间的关系，有助于你更清楚地设计 AI 系统架构，也更容易判断一个产品到底是在做“协议层”“执行层”还是“能力层”。
