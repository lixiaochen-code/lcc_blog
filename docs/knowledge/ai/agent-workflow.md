# AI Agent 工作流设计

## 背景

AI Agent 不是单次问答接口，而是一套能够围绕目标持续规划、调用工具、观察结果并修正行动的工作流。它适合处理跨步骤、跨数据源、需要不断确认上下文的任务。

## 核心组成

- 目标理解：把用户输入转成明确的任务边界和成功标准。
- 上下文管理：读取当前知识库、会话历史、用户选中的文章和必要的外部资料。
- 工具调用：在需要时调用检索、文件读写、数据查询或业务 API。
- 结果校验：检查工具返回是否足以支持下一步，避免凭空编造。
- 用户确认：涉及写入、删除、发布等动作时，需要用户确认后执行。

## 适用场景

- 根据一组资料整理文章。
- 比较多个方案并生成决策建议。
- 持续追问后迭代一份草稿。
- 在权限允许范围内辅助维护知识库。

## 设计原则

Agent 应该优先使用已有上下文。外部检索只是能力之一，不应该因为开关开启就强制调用。只有当前上下文不足、信息具有时效性或用户明确要求外部资料时，才需要检索。
